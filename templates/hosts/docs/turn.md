# 回合细则

开局与常用动作见[主持卡](../README.md)。本页管两阶段回合、事实核实与人物登记。命令参数以 `turn ops`、`turn schema payload` 和具体错误提示为准。

## 一回合的流程

1. **收无状态供给。** 一句玩家话一个事件。钩子只做只读无状态快照注入（场面、到点安排、待办任务、在场及点名人物、关键装备），绝不自动写盘开脏草稿。未启用钩子或需要登记玩家原话时用 `turn open --player "玩家原话"`，也可直接 `turn do ...` 自动开草稿。压缩或恢复先按主持卡开场，有未提交稿看 `turn show` 再续或 `turn abort`。场外提问不提交、不推进。
2. **只补当前缺项。** `turn more --npc "名字: 短话题"` 查人物，`look` 查设定，`find` 查旧事，`items` 查物和持有人，`price` 查价格，`rule 英文名` 查 SRD，另查 `ledger`、`schedule`、`bills`。回合内查到的材料都算当前依据。
3. **Phase A 裁定与试算。** 按[查阅后的主持裁决](#查阅后的主持裁决)演人物和世界，解决玩家这回合的行动。掷骰、长推进、战斗或周期结算先 `turn do ...`，引擎立刻返回 `【Phase A 回执】` 与骰果、数值变化，草稿保存已定动作与骰果。钟点以开稿日为准，跨日明写 `D160 07:00`，按真实时长推进。
4. **Phase B 一次提交。** `turn commit` 从标准输入读 YAML 头、单独一行 `---` 和完整正文。至少写 `title`、`ruling`，需要时写 `do` 或 `facts`。示例中的名字、地点和时间都须换成本回合实际内容。

   ```yaml
   title: 问取货时间
   ruling: NPC判断（经手人）：说三天后交货（sample-pickup）。
   do:
     - schedule delegate sample-pickup --who 经手人 --due-day 160 --at 12:00 --what 把做好的货送到约定地点
   ---
   这里放给玩家看的正文。
   ```

   `do:` 写了就是全部动作，不写则沿用 `turn do` 草稿。Phase B 仅检验硬不变量（载荷格式、pending 未完成项、随身装备、持物、物价表、禁漏 `gm/`、禁元叙事与高频重复词），不再用正则猜测数字或正文措辞。被拦后照提示修对应部分；只改正文用 `turn commit --sub 旧 新`，只改头或动作则交变动项、分隔线后留空。
5. **发正文。** 成功后原样发出返回的完整玩家版本及自动附加机制块，随即停下等玩家；有后台任务时按[宿主协议](hosts.md)派发，不等后台完成。Stop 只在确实误漏时补核。[叙述与日期](narration.md) · [无钩子及派发说明](hosts.md)

## 查阅后的主持裁决

主持负责演出世界的新行动与变化。旧记录用来约束已定事实；地点钥匙只回答它覆盖的空间、时刻及内容。把玩家此刻要查证或改变的事写清，先核已有答案，再按实际情况处理。

- **回顾可做的事。** 玩家只问「这里有什么可做」「明天有什么好玩的事」时，从塔莉娅的经历和已知消息里回顾。可以说她知道去哪里看告示、可以找谁询问；旧情况注明时机，新内容等实际查看或打听。人物主动递话或现场事件照实际发生演出，塔莉娅确实看到或听到才算获知。
- **已有定论或现有手段已查尽。** 直接给角色按行动能确认的结果，以及仍无法判断的范围。空处可以搜空、机会可以错过。只知道某人物尚未被证实知情时，保留他的知情边界。
- **当前局部确实未定（“空白即画布”）。** 只要符合当地风貌且不篡改旧事、不私发正式支线 `Q`／史诗／魔法宝堆或核心秘密，玩家打听、闲逛、翻找、试探时，主持应主动结合当地风貌或一次检定现场长出鲜活细节、普通配角、小物件与次要线索，并随回合用 `--new`、`new-item`、`replace-in` 落盘，不一律判成“没发现更多”。确实搜尽、问尽才如实给出已无新获。
- **实际打听招工或查看公告。** 有机会组就照当期结果交付；查不到匹配组时，根据本地行当与当时情形当场补定公告板或接洽人。一次性的消息随回合记录，可复用的板位记进地点卡。
- **当前行动依赖幕后答案，或局势需要备成冒险。** 用[现有世界层入口](setting-prep.md)与 `prep context` 派发子代理补所缺的动态、真相或后续地点；当前就要知道的才开前台，其余可走后台或[四层备戏](agents/adventure-prep.md#四层备戏与场上使用)。

## 统一人物查阅与交付

优先用已递材料。人物近况按草稿场面查 `turn more --npc "人物: 话题"`，查不在场者加 `~名字`。已备答案、已结钱物和定时结果回执直接使用；能由已有数值和明确假设完成的估算在主持侧完成并注明假设。

一般寒暄与小互动按当前条件和性格演。确缺承重事实且人物在场才按[前台窄答配方](agents/world-planner-quick.md)派发窄答；设定或局部地图缺项按[设定准备](setting-prep.md)核实。独立查询可同批，派发按[宿主协议](hosts.md)。

## 承重事实与人物登记

谁做过什么、知道什么、人在何处、物属于谁、价格、方向、时长与距离，以供给、工具读到的记录和现行设定为准。无记录不能直接证明不存在。底卡管稳定身份与性格，现状以 state 和勘误为准。方位与路线先核地图与已定路线，不凭传闻或一段耗时硬推全程。

- **知情与受众。** 当面发话或实际听见的人写 `NPC判断（名字）：`。同一见证逐名合写 `NPC判断（甲、乙）：在旁听清……`，不同判断分写。旁人不会因在场自动听见私话；不当面写 `~名字`。供给省略的秘密不判知情，核实用 `recall 人物 --full`。
- **事实、心境与关系。** 转告、信件、秘密、约定、打算、变更及了结记 `facts`，透露可发现秘密写 `secret: S-…`。留存感受写 `心境:`，身份变化写 `关系:`，了结写 `resolve`。每对人物心境按到期或化解管理，来历查 `relation view`。
- **新人物及现状。** 用 `turn more --new "npc-x=名字,别名"` 登记并自动建底卡与性格骨架；已有实体只加别名。稳定外貌、身份与本领用 `replace-in` 写入底卡，住处现职用 `npc_status`，去向用 `enter` / `leave`，首次报年龄用 `age`。
- **新地点和话题。** 查 `look` 再登记，`loc-xxx@loc-城=名字,别名`、`topic-xxx=词,近义词`。
- **物、交易与钱。** `items` 核库存与持有人，`equipment` 核穿戴。取得 `new-item`，穿脱与移动 `put` / `give`，`hold --why` 管随手持有，预算与成交 `price` + `buy` / `sell`。收支、欠款与应收走 `pay`、`debt`、`receivable`、`schedule`。
- **承诺、定时与任务。** 托付用 `schedule delegate`，提醒用 `schedule remind`，惦记用 `schedule add --kind concern`，[定时结果](scheduled-results.md) 管回执与报告。`Q` 任务按 `quest discover / accept / progress / resolve` 推进，结项时按工具结果报经验。

## 检定、推进与世界提示

- **检定（低烈度直接骰，高风险先确认）：**
  1. *低烈度*（搜查、潜行、街头打听、手艺辨识、讲价等）：玩家尝试后定合理 DC，直接 `turn do check 类型 --mod N --dc N [--adv|--dis] [--secret]` 掷一次并写入同回合。常规寒暄或按已有约定办事免掷。
  2. *高风险*（掉血、陷阱、开战、彻底谈崩、暴露身份或重大不可逆损失）：先公开检定类型、加值、DC、成功收益与失败代价，等玩家确认再掷。
  3. *双向四档结果*：**大成**（超 DC 5+ 或自然 20）附带额外收益或线索；**达标**正常办成；**低烈度失败**优先走推进式失败（多花时间或小钱问到线索、踩出新转向等），不白耗回合；**高风险失败**照已公开代价触发。
  4. *一次定局*：同法只掷一次，不原地连刷高骰；条件实质变化才重算。房规优先，再查 SRD。
- **推进截停与受控快进。** 遭遇或可察觉关键节点触发即停在该刻交还选择，CR 0 点缀不截停，`互动: true` 照常截停。已遇遭遇用 `agenda encounter` 查看。受控制照 [受控规则](combat.md#支配和控制) 与 `control` 动作推进。
- **场景与备戏。** `agenda here` 翻开已到达的地点钥匙，`agenda spot` 查野外去处，`agenda confess` 在当面逼问或交底时翻开供词卡。已配置公告组与周期机会用 `opportunities`，支线和主线按[四层备戏](agents/adventure-prep.md#四层备戏与场上使用)运转。
- **后勤与休息。** 长休用 `advance --as 出神|睡`，以引擎输出为准。

## 提交与并发恢复

工具只拦结构、数值与硬边界冲突，按提示修改对应字段即可；不再把格式或文案警告转入待审积压。旧事件写错用 `勘误:` 登记，查旧事优先采用〔勘误〕〔更正〕。另一会话先提交时，先看新事件再 `turn rebase` 或 `turn abort`。
