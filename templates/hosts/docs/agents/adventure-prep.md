# 四层备戏配方（世界层按需读取）

2026-10-29 玩家定。本配方不另开逐回合任务，不把生活换成固定任务菜单；准备不等于玩家接受，不推进时间。

## 频率与分工

| 层 | 何时准备/运行 | 用什么 |
| --- | --- | --- |
| 普通工作、车队 | 按各 opportunities 组周期，查询缺当期实例才经动作刷新；长期离开直接取当前批 | 登记条件与模板，报名、工期、完成、付款分别处理 |
| 遭遇 | 路上昼夜各检定一次，仍用地区概率与稳定盐；近期新路线按约两周前瞻备表，同一伙照面后修订 | 已备地区表与现成小场景，旧点缀不截停 |
| 支线 | 独立定居点和全战役的熟人各按带年份旬键检查，地点定额及递话见下文 | 已备完整的悬赏或短冒险，优先改编现成作品 |
| 主线 | 起手目标预备，后续按明确的任务结果、证据或一次性行动排队 | 史诗记录总目标及各幕，阶段沿用 Q，实际接触才递线索 |

素材不足才选书或检索，不每旬重搜。普通工作可以直结正常履约；意外与必要交涉才进入场景，报酬不凭空追加。遭遇可结束，冒险可收尾，持续关系照实际交往登记。四层通过既有卡引用，经验与收益不重复结算。

玩家要办的事按实际目标识别。公告板常用于日常工作、周期招募和目标明确的一次性悬赏，例如寻物或猎怪。纸面写清委托人、目标、怎么交付、赏格和确有的时限。主线和支线也可通过公告开始，前提是有人有理由和权限在这块板上公开这些信息。同一任务可以从公告、人物接洽、现场或物证入手。短冒险可以是有独立收尾的支线，也可作为主线的可玩章节。塔莉娅办悬赏时若实际撞见别的事情，照所见所闻处理，悬赏本身按说好的条件结清。

## 任务定义

备主线或支线用 `agenda quest set Q-… --as-of E…` 从标准输入登记 YAML。修订原定义时同一命令加 `--replace`。定义留在世界侧，同一个 `Q` 贯穿所有入口、阶段和结局。旧编号和已使用的阶段编号继续沿用，写公开用语时按塔莉娅在对应阶段实际能知道的内容。

- `id`、`kind`（`main` 或 `side`）、`title` 和 `goal` 写编号、分类、可公开的标题和任务整体目标。主线写清与塔莉娅在意的事有什么关系，安排可取得局部成果的阶段。支线能自行收尾。
- `entries` 以入口编号为键。`kind` 为 `board`、`rumor`、`site` 或 `evidence`，`ref` 分别写公告组、传闻、地点或物证 ID。`text` 写公开内容，传闻沿用其 `原话`；`objectives` 依入口列出会得知的阶段编号。`board` 的 `publisher` 写有权贴告示的已登记 NPC。入口可写生效 `start` 和失效 `end`，日期根据接触机会起止确定。
- `objectives` 以阶段编号为键，`text` 写可操作的目标，`after` 可列前置阶段，`requires` 可写实际持有物品 `item` 或已知事实 `fact`。入口点名的阶段要先经该入口得知。单靠前置阶段衔接的目标，应当能从已有成果推得。用事实判据时，按既有回合载荷用指定编号登记实际查实的事。预先取得物证、绕过预期解法时按实际结果衔接。
- `outcomes` 以结局编号为键，`text` 写可见结局，`after` 列达成依据所对应的阶段。新任务用 `xp_cr` 写实际非战斗成果对应的挑战等级。旧 `xp` 定义继续读取。备戏用 `refs` 引用相关记录，地图、证词、当事人和钱物来源仍写在原卡。钱物实际交付才记账。

旧 `front: {id, step}` 用于读取此前已发生的证据。新准备的后续进展用实际接触、物证和事实判定。

## 主线的多幕准备

先确定贯穿多幕的一个长期问题、各方想取得的结果，以及它和塔莉娅已经在乎的人或事有什么关系。远处的人按各自的理由行动。备下他们必须做到的关键步骤、机会出现的条件，以及她能在哪里改变结果。每幕都有一件玩家现在能动手并取得可见成果的事，先备到能够实际游玩。后续先备相互衔接的候选目标、关键地点和可能后果，随实际行动落实。

用 `agenda epic set ID --as-of E…` 登记长篇及就绪条件。每条史诗先有能完整游玩的起手目标。后续各幕先定具体可做的候选成果与触发所需的事实，命中才派发相应任务。可接触的第一步写实际地点、人物或可传到的消息，后续目的地可以跨城或跨地区。一个阶段派发对应一条标准 Q，在定义里写 `epic: {id, act, slot}` 并完成原派发回执。

让前一幕的成果影响下一幕能找谁、还能走哪条路、对方还剩什么手段。终局所需条件写成现实障碍与实质成果，来自游历、盟友、支线及提前取得的物证都可以满足。按实际已做到的事收束。对手有具体时间、人物和地点的行动按一次性安排执行，只有登记了接续意向的行动才在成功或失败后派一件准备任务。下一项要么有明确时间和局势变化，要么写可核验的停手依据。没有新的条件和行动时，史诗留在当前局势。

## 素材索引与改编

世界侧索引在 `gm/prep/materials.yaml`；它只是候选出处与使用情况，不是第二本世界事实账。不读给玩家，不塞进主持供给。来源要有本地可读路径及篇章/页码，或完整可读网页链接；简介只算候选。先筛约 4–6 个概要，只精读选中篇。网上用作者/出版方可读资料，不自动购买或下载来历不明整书。

先审已备内容与锁定事实，合适的补足，不为套作品推翻旧事、重抽宝藏。保留原作地图连接、信息分布、人物利益冲突、特殊机制与可选路线；只取一句梗概再重写全篇不算完成改编。地域/年代/入口/身份合理适配，记来源及必要改动，不复制整段原文。

选材看玩法结构差异，不只轮换救援、打捞等名目。评估塔莉娅全部形态、法术、同伴与行动数量，不能只按术士等级套原作。飞行、变形等自然绕过障碍照准；核心玩法失效且需大改就换篇，不临场封能力，不机械堆敌。非本版数值先转换，怪物/陷阱/特殊物件规则可查。

每个完整冒险备齐：

1. 合理入口、目标、预计体量与范围、退出及完成条件；不定玩家行动、顺序、情绪或必胜结局。
2. 核心地图/地点连接、区域内容、线索路径、人物目的与知情。核心真相入场前有答案。涉及调查时，为决定能否继续的关键推断准备三条独立可核的线索，写清各能证明什么、从何接触、能把人领到哪一步。同一证词的复述不算独立证据。必要时给人物供词卡，场上按已知逐步揭示。
3. 两种以上可行处理思路所需条件，允许玩家另想办法；时限仅在确有原因时设置。
4. 具体收益来源、取得条件、付款方/账户；宝藏按既有规则备，核对风险与投入。不能只奖抽象人情或更强敌人的线索；可以错过或失败，不保证拿全。
5. 有自身目标的新人物与可能后续来往，已有 NPC 只在身份与知情合适时复用，不预定友谊。
6. 不介入、部分完成、失败与完成后的局部状态；至少有不要求解决长线强敌的候选。即使是长线支线，也须有独立成果与退出方式。

审稿时看玩家听完开场能否说出当前目标、第一步和怎样算取得成果。给按不同顺序接触的情况备好反应，尤其是先找到了物证、联系人缺席或机会已经结束。主线章节可用地点卡的 `关联长线` 和 `可介入机会` 指向相关任务和阶段，写明实际成果会影响哪一步。先写可以改动的事实与可见后果，再决定下一段还需备哪些场面。

任务定义串起目标与结局，场面细节用 site / secret / rumor / schedule 留在相关卡。只回“已登记”，来源选择和审核结论放世界维护侧笔记。

## 遭遇小场景

优先改编现成遭遇；只补当前及近期野外路线，沿用原覆盖、概率、盐与同一伙身份，已锁定内容不重抽。交易、人物矛盾、环境、奇景、战斗可能均可；不必每项有任务、奖励或秘密。

可互动项备：在场者、正在做什么、初始距离与可见迹象、目标/态度、可交涉或利用条件、收益/代价与来源、脱离办法。骰子到真正触发才照规则掷。普通人交易不另编宝藏，不为放魔法物品绕过宝堆机制。

背景人流与主动交涉的共同口径见下文[四层备戏与场上使用](#四层备戏与场上使用)。

接口仍是 `agenda region set reg-…`：原有 什么/几个/在干什么/先察觉/一伙/照面已修 保留。需要玩家决定的项写 `互动: true`，即使 CR 0 也会截停；false 或省略沿用旧规则，不表示强制略过危险。预备笔记可写 `场景: {距离: …, 可见: …, 目的: …, 条件: …, 收益: …, 脱离: …, 出处: …}`，各值是非空文字，带场景必须互动 true。什么可写 SRD 卡、世界人物或场景名；场景名不代表新增怪物卡，开战仍查实际战斗卡。

`先察觉` 只放可见内容；场景里的目的、条件是裁决笔记，触发时才递给主持，不原样向玩家说。触发时日志存笔记快照，换会话可用只读 `agenda encounter` 重看最近两天最新已遇遭遇（本会话草稿已触发的也可读）；不解锁未遇表项，不受后来改表影响。快照只说明起始局势，后续以实际事件为准，不代表人还在原处。没有复杂内容的互动项不强制加全套字段；足以直接运行的场景才算备好。结束后只记实际发生的人物/物品/事实，有可独立核验的定时变化可用已有安排；重复身份照既有结果修订，不重置成陌生人。

## 目的地补设定与高空旅行

新目的地的地理/年代/人物准备按`docs/setting-prep.md`，用setting用途检查衔接本配方。到地区不等于必备完整冒险；business/explore只备当前事项，已有可用内容直接引用。地区表/site存在不代表整个地区已备齐。

长途默认高空巡航，不逐一准备飞越地区或套地面遭遇；只准备目的地、已计划落脚点和实际相关人物。临时接近/降落再补当前现场。短冒险的飞行/变形绕过照准；不为留出备戏时间临时封能力、强加天气或把原任务搬过去。

## 四层备戏与场上使用

- 地点和熟人各用同一套任务定义。新制定义写 `source: location|acquaintance`，地点来源写 `home: loc-…`，熟人来源写 `contact: npc-…`。每个派发最多交一条。熟人有理由介绍已有支线时，为该 Q 登记新入口，保留原来源及进度。
- 人口不足 100、100–999、1,000–9,999、10,000 以上分别有 0、1、2、3 个地点名额及 0%、20%、40%、60% 的每旬新增概率。独立定居点规模按[明确尺度与有来源的关联](../setting-prep.md#明确尺度与有来源的关联)在 `setting set` 中填写 `context.population` 或 `size`。强盗堡容量为 1；辖下街区和普通路过点接入所属范围。
- 地点按地点 ID 和带年份旬键固定结果。已备可用、已知、跟进中的任务及待交付的命中各占一个位置。同一 Q 的多个入口合计一件。满额记一次检查，有空位掷中才备一件。结项或搁置释放位置，下次正常旬检查。寻回或交付、调查或追查、探索、交涉或调停、排险五类等权抽签，允许重复。照回执抽中的类型结合当地人物与环境备戏。
- 熟人全战役每旬一次，33% 掷中后抽一个已实际来往、目前同场或有实际同行、当面约见依据的人。按他的动机写需要帮的事或可以介绍的当事人。发布前备齐可玩过程。候选暂无合适事可 `task done ID --why 原因`，结果沿用这个旬的原掷值。
- 新作的两种支线共用三次独立抽取。五种类型各占 1/5；体量 d6 的 1 为小委托，2–5 为完整短冒险，6 为高危险。高危险至少备一件现在可取得的成果。熟人介绍既有任务时沿该任务原来的入口目标、强度和奖赏。
- 强度用 `difficulty_basis` 写当地实际障碍、涉事方和风险，并按每个结局的非战斗成果给 `xp_cr`。战斗经验沿战斗结算。已知敌人、地形和能力照世界内容核定，风险与收益从局势得出。
- 额外实物按任务类型和另一个 d6。寻回或交付、交涉或调停的 1 是委托实物。调查或追查的 2 是对手随身，3 是宝堆。探索的 1–4 是宝堆。排险的 2 是对手随身，4 是宝堆。其它骰面只保留实际既有酬金和物资。奖励按委托人财力、对手持有和藏宝来历选。
- 新设宝堆先用 `agenda quest draft Q… --as-of E…` 登记任务，再以 `agenda site hoard LOC --owner … --reward Q…` 在实际地点备齐宝堆，最后正式登记 Q。已存在且仍完整、相符的宝堆直接引用。每个真实地点宝堆只掷和领取一次。实际发现才用 `loot`，新设宝堆须登记对应 `found_fact`；自由探索发现时同样可以登记。私人委托或对手物件也对应现存的独立实物和持有人，按实际移交或搜获用 `quest reward`。
- 公告悬赏写 `commission: {giver, handoff, reward}`，目标在 `goal`。查证或探索需要准备实地时，用 `sites` 引用相应的地点钥匙。传闻可用 `支线任务: Q-…` 预先标明归属，定义完成后才递。旧短冒险已经领取的回执继续按原要求验收。
- 日期可浮动的支线写 `clock: discovery`，未发现可待命跨旬。首次实际获得可行动线索后满十个游戏日仍未接手则搁置，旧知情保留。已接手按实际约定。任务有真实期限时写 `clock: world`，按世界里的时间和依据开放、截止。
- 史诗在本地的目标可由阶段任务承载，也可以被已存在的独立支线影响。登记具体局部成果与后续可核验的影响。旧势力线里已发生的人物关系、见闻与后果可作为支线素材，沿原地点或熟人入口准备。
- 保留逐场互动，不引入停工期结算或抽象联系人。抵达城市、完成一段事情、入口失效或玩家没有方向时，备戏核对她已经知道的入口、下一步、吸引力、可行性和局部成果；只把她已经实际得知的内容算作已知入口。两三个方向只是参考，不强制任务菜单，不凑数。她已有明确目标时，优先准备那个目标的当前局势和可验证信息；想休息或离城时照她的选择。
- 备当前冒险时核谁有理由采取下一步、她如何碰到实际后果。玩家追问未结目标但只得到旧信息时，核下一处可查现场和对方是否会主动接洽，按[回合裁决](../turn.md#查阅后的主持裁决)补所缺的一步。强敌仍强，先提供能取得独立成果的局部行动。短局势优先已有后果、Adventures in Faerûn 和 Fizban 素材。
- 有动机和知情依据的主动邀请、请求或递话，用 `agenda rumor set` 的 `主动来找: npc-…` 登记实际会开口的人；`在` 写准确的接触地点，`原话` 写对方会说的内容，`关键词` 选 2–4 个这条消息特有的词。按准备所需时间定 `从`，按实际机会定 `到`。场面具备接触条件时，供给另递【主动来找】，主持让对方开口，留给玩家决定是否跟进。实际写出至少两个该消息特有的关键词后用 `heard` 记已听。人物不在场或主持还没演，留下未听状态。定向递话不抵当地公开冒险入口。一次性的局势变化有明确时间并能由既有规则办理时，沿用安排并在实际可见时交付。
- 泛问「这里有什么可做」按[回合裁决中的回顾规则](../turn.md#查阅后的主持裁决)答。塔莉娅实际打听、察看或探索时，按她的行动核目前能接触什么。需世界层补时，先 `setting check 目标 --use explore --topic 主题`，缺项再用 `setting request`，世界代理通过 `prep context` 与一锤子 `setting set` 交付后由现场或传闻入口递出。
- 普通问车、看墙可用 `opportunities [组ID]` 查日常条目，`--all` 可看过期或婉拒项。塔莉娅实际到板位并看板时用 `turn do opportunity read 组ID`，适用的公开剧情告示随回合交付。日常首次生成或本期刷新仍用 `turn do opportunity refresh 组ID`；同周期重查、换问法和提交重算沿用原批次。换地点按真实路程推进。未匹配到机会组时，现场询问和看板沿[回合裁决](../turn.md#查阅后的主持裁决)处理。
- 只有双方说定才 `turn do opportunity status 条目ID --status 已报名 --why …`，同时按原规矩登记任务或约定。婉拒、结束、取消也用 status。实际看板登记已知的剧情入口，报名、扣钱、奖赏和移交另按实际行动登记。
- 首批保留已公布日期、工钱、条件和告示错字。新批只从登记模板生成，固定费用引用物价表，工钱/赏格沿用有出处的约定，不随机编价。告示原文与背后真相分开，关联剧情按原卡核查；日常表不能揭露关联秘密。普通换贴日不代表旧工作已结束。季节不适用时停用对应模板，不按夏季参数生成冬季车队。
- 表规则 `world/opportunities.yaml`，实例归 state 的 opportunities（只经动作改）；维护用 `opportunities 组ID --migrate` 补登 initial，幂等且不覆盖已有条目。不逐日追跑玩家离开时错过的刷新。记录变动后跟存档重算，不能重抽已确定的班次。
- 公告组可以用 `read_at` 指定实际看板地，沿用粗粒度地点 ID 时可用 `read_description` 指定板位的场景描述。例如旧港沿用 `loc-old-harbor`，实际看板时场景描述为「灯塔下雇工墙」。这些字段用于实际读板，日常问讯和刷新继续用 `at`。

### 地域与年代

- **地域与年代（2026-11-10 玩家定）**：南方与旧帝国按1502年、当前地点和实际接触对象演，不将各地套成同一种剑湾城镇。准备与使用时核当地生态及畜群、族群与语言、宗教与权力、贸易和待客习惯；让已登记的差异落在问路、吃住、市场、劳动、运输和公共交往中，不只换服装、菜名或建筑外观。按眼前活动取用，不每回合罗列地方风物、不凑遭遇或任务。同一地区的人有不同经历和判断，种族、国籍与信仰不自动决定态度；宗教和政治背景不自动变成盘问、收费或冲突。
- 原典旧时代、魔法瘟疫及第二次大分裂后的明确变化、1502年推定和本团补定须在设定来源分开。历史制度、旧君主与驻军不直接当今日现状；无新资料也不擅称文化消失。普通畜群、制品与迁徙习惯依具体地点、季节、旱年和既有记录准备，未写过不补成她早就见过。公开常态归地点/地区底卡，备选互动沿现有机会表、地区表与地点钥匙；准备不增加玩家知情、到访或已发生交易。
- **背景人流与互动分开**（2026-11-02 玩家定）：远处南行的人、井边等水的人等常态人流，没有向车队提出请求，也无紧迫危险或通行障碍时，按 CR 0 点缀准备，在沿途叙事中一两句带过，不因出现陌生人就截停。实际向车队求助、提出交易或形成其他需要回应的选择时，备为互动项，触发后照常在选择前截停。准备时将背景与主动交涉分成表项，标记、可见迹象与行为保持一致；不能把已经主动求助的人写成点缀略过，也不能把背景人流临时升级成求助来截停。玩家主动接近背景人物时，照其实际行动交互。已触发的遭遇沿用当次快照，不追溯改成点缀。
- 备搜查、探索和交涉时，若现场有值得验证的疑点，备下可见迹象、进一步能查出的具体信息和失手后仍可尝试的办法。现场照实际行动取用，检定按[回合细则](../turn.md#检定推进与世界提示)。

日常表仍通过原有查询提示使用。同场可接触的短冒险入口都能进供给，优先递本会话尚未递过的。主持按现场自然呈现，把是否跟进留给玩家。正文实际告知后才在该回合载荷用 `heard` 登记对应传闻；看过提示、玩家有别的事或听到喊声却未听清内容时，保留未听状态。
